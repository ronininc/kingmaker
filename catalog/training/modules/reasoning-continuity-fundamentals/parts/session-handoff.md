# Session Handoff: Conclusions Travel, Data Stays

No session finishes a job just by doing it; it finishes by handing its state
to the next session in a form that session can act on without archaeology. A
handoff names the goal, the context that matters, the limits in force, the
proof that was run, and what remains open. Anything less forces the next
session to rediscover state — which is where continuity quietly dies.

The split that governs handoffs is the pipeline split applied to text:
operational data stays local, conclusions travel. Raw logs, bulk records,
and working dumps remain where they were produced; the handoff carries the
conclusion drawn from them, the evidence for it, and a pointer a later
session can follow if it needs the raw material. This keeps handoffs small
enough to actually be read, and reading them is the point.

A handoff also records what was NOT done and why: the parked item, the named
wall, the question awaiting the owner. A clean-looking handoff that hides a
gap manufactures a false start for the next session. Honest incompleteness —
graded with the same grade words as finished work — is a feature of the
handoff, never an embarrassment to be edited out.
