# Method — Headscale Node Provision (config + enrollment plan)

A method file (owner item 15): read by the conductor (`lib/method-conductor.mjs`) and executed
step by step. For a node/Headscale-class task: prepare everything a node joining the family mesh
needs that can be prepared locally — inspect the target state directory, check for the Headscale
binary, generate the control-plane config and the access policy in the shape of this tree's own
`lib/headscale.mjs` store layout, write the enrollment plan, and verify the generated files.

Doctrine carried from `lib/headscale.mjs` (program item 16): NO VPS, ever — the control plane is
Headscale embedded in the ORIGIN installation; family devices never install control planes of
their own, they join the origin with an enrollment key scoped to joining and nothing else
(`mesh:join`). Key strings are handed out once at mint and never stored — so this method writes
an enrollment PLAN, never a key. Starting the control plane is activation's act, supervised by
`lib/runtime.mjs`; registering a node needs that live server. Those two steps are therefore
DECLARED steps below: the conductor records them in the trace as declared-not-executed and never
fakes a running control plane, a joined node, or a minted key it did not mint. The inspection,
generation and verification steps are conducted for real.

## Steps (prose mirror)

1. **inspect-state-dir** — Look at the `headscale/` state directory in the workDir: does it exist, what is already in it. (lib/headscale.mjs treats a config whose bytes drift from its activation record as REFUSED, never silently repaired — an existing state dir is reported in the trace, not papered over.)
2. **check-headscale-binary** — Locate a `headscale` binary: the caller's `headscaleBin` input (in this tree, the vendored `vendor/headscale/headscale-<platform>-<arch>`, pinned by `vendor/headscale/pin.json`) or PATH. Existence + executable bit only; the conductor never runs it from a method file.
3. **render-config** — Generate `headscale/config.yaml` from the method's inputs: server URL, listen address, base domain, Noise/DERP key paths, sqlite database, MagicDNS — the pinned release's shape as `lib/headscale.mjs` writes it.
4. **render-policy** — Generate `headscale/policy.json`: one family group containing the node user, family-to-family accept.
5. **write-enrollment-plan** — Write `headscale/enrollment-plan.json`: node, user, server, `mesh:join` as the only capability, and the note that key minting happens at activation and the key string is never stored.
6. **verify-generated** — Re-read the generated files and confirm the server URL, base domain, node name and family group actually landed on disk.
7. **declare-serve** — DECLARED: `headscale serve` belongs to activation + the runtime supervisor.
8. **declare-register-node** — DECLARED: node registration needs the live server and the node's key.

## Failure modes

- **No binary found** → steps 1 and 3–6 still conduct (config preparation does not need one — the same posture as lib/headscale.mjs's `bootstrap: 'pending-binary'`); the trace says plainly the binary was not found, and steps 7–8 remain declared.
- **Existing config drift** → out of this method's scope: activation (lib/headscale.mjs) owns the drift refusal; this method reports the existing state dir in step 1's trace result.
