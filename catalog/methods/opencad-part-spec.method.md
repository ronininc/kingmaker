# Method — OpenCAD Part Spec (parametric part → OpenSCAD source)

A method file (owner item 15): read by the conductor (`lib/method-conductor.mjs`) and executed
step by step. For an OpenCAD-class task: take a parametric part order and produce the real,
renderable artifacts locally — a part spec record and OpenSCAD source generated from the
method's parameters — then verify the generated source carries the ordered dimensions.

No CAD binary (OpenSCAD / FreeCAD) is installed on this node, so the meshing step is a DECLARED
step: the conductor records it in the trace as declared-not-executed with the exact command a
node that has the tool would run. The conductor never pretends an STL exists when none was
produced. The tool checks, the generation and the verification are conducted for real — and the
parameters live in this file's `inputs`, so editing a dimension in the file changes the
generated part with no code change.

## Executable block


## Steps (prose mirror)

1. **check-openscad** — Is `openscad` on PATH? Existence + executable bit only.
2. **check-freecad** — Is `freecadcmd` on PATH? Same check, second tool.
3. **inspect-workdir** — Record the conduction workDir's state before writing into it.
4. **render-scad** — Generate `<partName>.scad`: a parametric plate (cube minus four inset through-holes) whose every dimension comes from this file's `inputs`.
5. **write-spec** — Write `<partName>.spec.json`: the order as a record — dimensions, holes, material, units, and the source file it was rendered from.
6. **verify-source** — Re-read both artifacts and confirm the ordered width, hole diameter and part name actually landed.
7. **declare-export-stl** — DECLARED: the STL export command, with the reason it did not run here.

## Failure modes

- **A CAD binary IS present** → steps 1–2 report `found: true`; the export stays declared in this version of the method (running external renderers is a separate governed surface) — a future version of this file can promote it, which is the point of the capability layer: the update is an edit to this file.
- **Bad parameters** (zero/negative dimensions) → the spec still records what was ordered; dimension sanity is the ordering surface's job, and the verify step proves the file faithfully carries the order it was given.
