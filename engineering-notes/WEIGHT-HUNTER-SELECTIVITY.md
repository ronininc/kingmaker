# Per-request weight retrieval audit

The current CLI loads library.json once per session, classifies/scans model metadata, chooses one model, and calls materializeLibraryModel only for that chosen model if not installed. It does not download every model. Selected full GGUF parts are downloaded only when the full cached file fails fileMatches; matching parts are reused. Release metadata listing is not downloading every release asset. A fully cached model with a valid Modelfile needs no network transfer. Ollama still requires the complete selected GGUF, not arbitrary portions.

Observed unnecessary work: chooseTaskModel called cachedLibraryTags for every catalog model on every new task. That stat/checksum-sidecar traversal can hash whole files when sidecars are absent/stale. It is not whole-library network streaming. Fixed cache lookup to competitive scoring tiers only, and skips it entirely when an installed top-scoring candidate wins. Metadata scoring is still O(library size); that is deliberately cheap selection, not tensor loading. Existing checksum sidecar trust behavior is unchanged, not upgraded security by this optimization.

Five deterministic tests: 101-model metadata fixture probes one winner; only one ensure invocation; installed winner has zero probes/ensures; ties preserve cache preference; excluded action lanes and disabled hunter cause no retrieval. Actual temporary cached GGUF-shaped four-byte fixture plus valid Modelfile results in zero fetch calls through the real materializer. This is transport/cache evidence, NOT valid inference weights or an on-device performance benchmark. No real model downloads were attempted on the low-space Mac.

Recent demonstration path bypassed hunter: scripts/prove-blender-workflow.mjs directly requests already installed qwen3:1.7b through localhost Ollama, then launches Blender. The recorded Blender failure was Metal initialization before Python workflow execution. These are separate runtimes; no evidence that the hunter caused that crash. No retry while free disk remains below the new 512 MiB reserve.

Cross-model forge remains a plan generator. Architecture/tokenizer fingerprints select suggested merge/graft/distillation strategies, but this module never performs tensor conversion or training. GGUF is a container, not a Linux-only binary. Compatible conversion must preserve architecture/operator semantics and be tested in the target engine; incompatible architectures need a separately implemented and evaluated training/reconstruction path. Existing plan metadata does not establish that path.

## Owner no-download direction

Default hunter now refuses a selection requiring fetched weights (`weights-not-local-download-disabled`), leaving its preexisting fallback lane unchanged rather than initiating a transfer. CLI's selected-model materializer is explicitly offline: missing/invalid complete GGUF or local Modelfile fails before network access. Tests prove zero fetch calls for missing offline weights. Internal caller opt-in `allowDownload` remains an explicit API choice, not enabled by CLI or any user turn. These changes do not assert partial-weight inference; the range API returns data portions with `streamedToOllama:false`. Existing installed execution is local; making arbitrary model portions executable requires a real supporting inference runtime, not a label change.

### Reversible pause and no hidden fallback

The calibration schema now exposes `weightHunter.retrievalPolicy`: `local-only` (current safe default) or `approved-download` (explicit future owner choice). No existing user calibration file was modified. CLI forwards that policy to both selection and materialization. A missing selected model during the pause produces `WEIGHTS_NOT_LOCAL`, not an automatic unrelated fallback. The execution-loop hook also refuses rather than silently falling back. This is a reversible pause on full-model downloading, not a ban on future verified streaming implementations. Neither option falsely enables streaming inference in Ollama.
