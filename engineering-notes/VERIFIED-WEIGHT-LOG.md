# Persistent weight verification log

`lib/verified-weight-registry.mjs` records local checkpoint SHA256, configuration SHA256, original runtime-source hashes, runtime ID/version, architecture and precise tested scope. Its content-derived key prevents incompatible runtime/config changes from reusing a result. Evidence is a separately hashed bounded JSON file; lookup rechecks checkpoint, configuration and evidence bytes before returning reusable evidence. Changed/missing files invalidate reuse. No weights, prompts, credentials, keys or user input are stored in the log itself.

The log is history, not admission. A caller must supply a genuinely successful scoped test receipt; generic JSON being recorded does not validate its assertions. A planned production adapter must validate its own receipt before recording. Neither recording nor lookup grants execution, paid entitlement, license, security certification or generalized quality. Weight-byte identity and tested execution are separate from authored/learned method skills. This can avoid rerunning the same verified scope, not avoid integrity checks or manufacture new training.

Scope is only eight-position teacher-forced forward equivalence on the exact PyTorch CPU implementation. No active model selection, installed app or remote repository was changed. The reusable operational runner is still in progress; this module is not yet an automatic global weight cache.
