# Same-version updates

The version stays 0.3.0. GitHub PRs and locally rebuilt apps are not published releases.

The update host's unsigned `latest.json` is only a locator. Before reporting availability, the client verifies the manifest's detached signature with its existing pinned release key and matches its tag/version to that locator. App identity, archive SHA-256 and installer-engine SHA-256 must be signed fields.

For a known installed release, a higher semantic version is an upgrade. Within the same version, an identical signed app archive digest is a no-op. A different artifact is newer only when its signed `createdAt` is strictly later than the installed signed manifest's `createdAt`. Equal, missing or invalid timestamps are **update-unconfirmed**; older timestamps/versions are rejected. Publication must preserve strictly increasing, truthful build timestamps when revising the same version. If timestamps cannot establish order, a future signed explicit build sequence is needed; unsigned asset dates, GitHub asset IDs and `latest.json` never supply ordering authority.

After app/config moves succeed, the installer atomically replaces `installed-release.json` as its last journaled move. It contains the signed manifest/signature plus hashes of the installed GUI, closed engine, payload manifest, Info.plist and CodeResources seal. The previous receipt is copied aside before atomic replacement and rollback restores it with the old app. Checking, downloading or starting an installer never advances provenance. Graceful interruption/failure uses the existing journal rollback; an uncatchable crash cannot authorize an update from a missing/mismatched receipt. The client also deep-checks the payload and runs macOS codesign --verify --deep --strict with the pinned certificate requirement over the entire installed bundle. A valid but locally re-signed resource change also changes the bound CodeResources seal.

Legacy installs without receipts, locally patched bundles, invalid receipts, or mismatched payloads return **update-unconfirmed** and do not overwrite local fixes, including on a higher-version offer. They require an explicit verified installer run to establish provenance. Never synthesize a receipt by associating an unknown local app with the latest remote manifest.

At apply time the client captures the approved app/receipt hashes, rechecks them after downloads and passes that snapshot to the detached installer. After staging and graceful shutdown, immediately before the first replacement move, the installer revalidates the pinned bundle signature and all approved hashes. Any app/receipt change aborts before the commit; it does not overwrite the changed local app. The guard is mandatory for updater-launched installers. The client rechecks local provenance and verifies that the downloaded signed manifest is exactly the digest checked earlier. Existing detached installer certificate validation, signed engine hash validation, app signature verification and transactional rollback remain in effect. No signing material, model picks or routing logic changes.

Validation: `node --test test/update.test.mjs test/update-revision.test.mjs test/update-receipt.test.mjs test/update-consent.test.mjs test/update-seal.test.mjs test/update-cas.test.mjs`. Receipt tests execute the production shell staging/commit/rollback blocks in temporary directories with test-only release keys; no live update is launched.
