# Private Kingmaker 4.5.1 assembly

This is an owner-lane candidate assembly, not a customer release. It checks out Kingmaker `ae55f9ac5dfa2b8fbba2044f6d5150ecd52a5982` and the approved TSS engine `4d514a623d51f78b0faed0d0edabd41b5e279cfd`. It does not enroll devices, publish, deploy, move update pointers, read signing keys, or notarize. The only signing is ad-hoc. It keeps the zip and provenance privately for two days.

**Before dispatch:** register or identify a dedicated, preferably ephemeral, owner-authorized macOS arm64 GitHub Actions runner with label `kingmaker-assembly-arm64`. Restrict runner access to this private repository. The workspace and runner temp must both be writable APFS with 32 GiB measured free before any checkout or download. Have Xcode CLI tools, Python 3.13, and GitHub CLI available. Standard and XL GitHub-hosted [macOS runners](https://docs.github.com/en/actions/reference/runners/github-hosted-runners#standard-github-hosted-runners-for-private-repositories) provide only 14 GB of storage. Do not substitute one or reduce the floor.

**Approved source checkout:** if the dedicated runner already has the approved TSS checkout, set the path-only repository variable `KINGMAKER_APPROVED_TSS_SOURCE_ROOT` for that runner. The workflow creates a separate checkout of the pinned commit; the source checkout is left unchanged. No credential is needed. Otherwise use a short-lived GitHub App token or fine-grained credential scoped **only** to `ronininc/TSS` repository **Contents: read** in `KINGMAKER_TSS_CONTENTS_READ`. Do not provide a broad credential or share it in chat. Kingmaker checkout uses the existing workflow token and signing credentials are not part of this path.

**Owner-approved runtime kit:** set `KINGMAKER_RUNTIME_KIT_ROOT` to a local input directory and `KINGMAKER_RUNTIME_KIT_MANIFEST_SHA256` to the exact approved SHA-256 of its `runtime-kit.json`. This is a new build input approval, not a credential. The kit contains these six ready-to-stage macOS arm64 runtime archives with each kind as its archive's single root:

- `voice-runtime`, `guardrails-runtime`, `guardrails-config`
- `agent-runtime`, `knowledge-runtime`, `playwright-browsers`

Manifest schema `kingmaker.ci-runtime-kit/1`; top-level `sourceCommit`, `engineCommit`, and `inputs`. Each of the six inputs has exactly one distinct `kind`, `archive` (safe basename ending in `.tar` or `.tar.gz`), byte `size`, and `sha256`. An existing Guardrails executable hash mismatch remains fatal. The installer tests never run from or write to the installed owner app. No old production bundle qualifies as a kit. The job verifies and expands the kit in disposable storage, compiles the exact engine, stages the six runtimes and known arm64 binaries, builds the exact Kingmaker payload and ASAR, and checks the complete private candidate with the real release inspector plus signed installer fixture tests. It won't silently omit a runtime to make a job pass.

**Once separately authorized:** dispatch `Kingmaker private harness assembly` from the approved workflow ref if available in Actions. If the workflow has not been added to the default branch, an explicitly approved push of the internal tag `ci-proof-kingmaker-harness-ae55f9a` at the exact reviewed workflow commit is the branch-only trigger. This is not a release tag. Do not push a tag, edit settings, or start a runner during review. An ordinary branch push never starts this workflow. An ad-hoc candidate still needs the existing owner-managed app signing, detached manifest signature, Developer ID installer and notarization, and exact distribution proof before any customer use.
